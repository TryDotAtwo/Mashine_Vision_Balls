# ClickHouse: основной порядок хранения

Основной CLI записывает серии в ClickHouse и строит сводки/графики из базы.
Файлы ниже являются экспортами. Настройка: [docs/CLICKHOUSE_RU.md](docs/CLICKHOUSE_RU.md).
Для локальной диагностики без сервера добавьте `--offline`; старый режим
одного объекта также требует `--offline`.

# Машинное зрение шариков

## Анализ серии: редакция 30.09.2026

По умолчанию `run_analysis.py` обрабатывает несколько окружностей в кадре,
сопоставляет их между кадрами и сохраняет сводку по траекториям. Старый режим
одного объекта и интерактивного просмотра доступен через `--single-ball`.

Короткий проверочный запуск на архивном видео без подтверждённого масштаба:

```powershell
py -3 run_analysis.py --video data/videos/Ball_For_MV.mp4 --frame-step 10 --max-frames 4 --measurement-mode pixel --min-ball-diameter-px 50 --max-ball-diameter-px 300 --tracking-distance-px 200 --output-dir output/analysis/check_series
```

Для реальных измерений задайте фактическую геометрию либо известный диаметр
опорного объекта через `--measurement-mode reference --reference-diameter-mm ...`.
Наличие чисел в шаблоне конфигурации не подтверждает параметры вашего стенда.

Сохранённую скалярную калибровку можно получить из CSV, содержащего наблюдения
только одного объекта известного диаметра. Ниже 4 мм и 0.01 мм — пример,
их нужно заменить измеренными значениями:

```powershell
py -3 run_analysis.py --calibrate-csv output/reference/measurements.csv --calibration-diameter-mm 4 --calibration-sigma-mm 0.01 --calibration-width-px 2100 --calibration-output configs/scale.json
py -3 run_analysis.py --video data/videos/Ball_For_MV.mp4 --calibration configs/scale.json --measurement-mode reference --output-dir output/analysis/calibrated_series
```

Если рядом с CSV есть `run.json` или прежняя сводка с `width_px`, ширина
подставляется автоматически. Калибровка хранит масштаб, его модельную
неопределённость, повторяемость, исходный диаметр, ширину кадра и SHA-256 CSV.
При другой ширине видео программа требует новой калибровки. Изменение объектива,
расстояния, среды или положения эталона тоже требует проверки масштаба.
Калибровка не корректирует дисторсию и преломление.

Выходные файлы нового режима:

- `measurements.csv`: все измерения с идентификаторами траекторий;
- `tracks.csv`: средний/медианный диаметр и разброс для каждой траектории;
- `frames.csv`: включая кадры без объектов и без доступного масштаба;
- `series_plots.png`: диаметры во времени, гистограмма медиан по траекториям,
  модельная неопределённость и изменение масштаба;
- `preview_sheet.jpg`: контрольные кадры с окружностями и идентификаторами;
- `summary.json`, `summary.md`: сводка;
- `run.json`: параметры, версии Python/OpenCV/NumPy, хеш исходного видео,
  хеши программных модулей и применённая калибровка.

Гистограмма включает одну медиану на траекторию с не менее чем
`--min-track-observations` наблюдениями (по умолчанию 2). Это распределение
траекторий: потеря объекта или пересечение может разделить один физический
шарик или сменить его идентификатор. Сверяйте результат с контрольными кадрами.
`--tracking-distance-px` задаёт допустимое движение между обработанными кадрами,
`--tracking-max-missed` — допустимые пропуски. Подбирайте их вместе с `--frame-step`.

При обнаружении круглой ячейки поиск ограничивается её внутренней областью.
`--no-cell-mask` отключает это ограничение для иной геометрии. Поиск окружностей
может принимать пузырьки за шарики; диапазон размеров и порог опоры на край
нужно задавать по условиям серии. Численная точность на стенде ещё не измерена.
Многобъектный режим формирует сохранённые графики; живой просмотр остаётся
в прежнем режиме `--single-ball --interactive-preview --live-plots`.

Проверки: `py -3 -m unittest discover -s tests -v`. Новые тесты включают две
движущиеся окружности, пустое видео, экспорт, применение калибровки,
несовпадение ширины, Unicode-пути, пропуски треков и приоритет CLI над конфигом.

Проект приведен к рабочему стендовому контуру:

- пакетный анализ видео с сохранением артефактов серии;
- два режима масштаба: `fov` и `reference`;
- явное разделение геометрии стенда и внутреннего диаметра ячейки;
- расчет массы испарившегося азота и требований к допуску ячейки;
- комплект документации для стенда, закупки и статьи.

## Структура

- `run_analysis.py` - единый entrypoint.
- `src/mvb/config.py` - шаблон и загрузка `key=value` конфигов.
- `src/mvb/pipeline.py` - детекция кругов, batch-анализ, preview.
- `src/mvb/experiment_math.py` - масштаб, погрешности, масса LN2, допуски ячейки.
- `src/mvb/reporting.py` - экспорт артефактов серии.
- `tests/` - unit-тесты.
- `data/` - исходные медиа и документы (не удалять).
- `legacy/scripts/` - архив старых `.py` до рефакторинга.
- `tools/reorganize_root.py` - одноразовая уборка корня (уже применена; при блокировке `debug.log` файл можно удалить вручную).
- `docs/PROJECT_AUDIT_RU.md` - аудит проекта и кода.
- `docs/LEGACY_CALIBRATION_22_4_RU.md` - разбор константы 22.4 мм в старом коде.
- `docs/UNCERTAINTY_METHOD_RU.md` - полный бюджет погрешностей, коррекция по уровню LN2 и методика CV-оценки ячейки.
- `docs/EXPERIMENT_MANUAL_RU.md` - подробная инструкция для стенда.
- `docs/PURCHASE_SPEC_RU.md` - закупка, приемка и спецификация оборудования.
- `scripts/generate_stand_manual_pdf.py` - генерация большого PDF-руководства от лица автора.
- `scripts/plot_measurements.py` - графики стабильности и гистограмма по `measurements.csv` (после batch-анализа; эпизоды «шарик» по `--gap-s`).

## Быстрый старт

Показать шаблон конфига:

```bash
py run_analysis.py --print-config-template
```

Пакетный анализ по геометрии камеры:

```bash
py run_analysis.py ^
  --video data/videos/Ball_For_MV.mp4 ^
  --measurement-mode fov ^
  --ball-to-object-mm 55 ^
  --zoom 1.0 ^
  --fov-deg 79 ^
  --min-ball-diam-mm 1 ^
  --max-ball-diam-mm 10
```

Пакетный анализ по референсу в кадре:

```bash
py run_analysis.py ^
  --video data/videos/Ball_For_MV.mp4 ^
  --measurement-mode reference ^
  --reference-name cell ^
  --reference-diameter-mm 40.0 ^
  --reference-sigma-mm 0.05 ^
  --min-ball-diam-mm 1 ^
  --max-ball-diam-mm 10
```

Расчет по ячейке и испарению азота:

```bash
py run_analysis.py ^
  --cell-inner-diameter-mm 40.0 ^
  --cell-inner-sigma-mm 0.05 ^
  --delta-level-mm 10.0 ^
  --level-sigma-mm 0.1 ^
  --target-rel-mass-error 0.03
```

Запуск из конфига:

```bash
py run_analysis.py --config configs/baseline_experiment.txt
```

Просмотр с живыми графиками (второе окно matplotlib; нужен `matplotlib`):

```bash
py run_analysis.py --video data/videos/Ball_For_MV.mp4 ... --interactive-preview --live-plots
```

Для нескольких шариков подряд задайте `--clear-track-after-lost-frames N` (после N пропусков трек сбрасывается, в `measurements.csv` растёт `ball_id`).

Сгенерировать подробный PDF-мануал:

```bash
py -3 scripts/generate_stand_manual_pdf.py
```

Готовый файл:

- `output/pdf/ivan_stand_manual_ru.pdf`

## Детекция (CV)

По умолчанию: несколько значений `param2` для `HoughCircles`, выбор кандидата по опоре на Canny; затем уточнение центра и радиуса по точкам края на полном разрешении (`src/mvb/cv_geometry.py`).

Отключение и тонкая настройка:

```bash
py run_analysis.py --video data/videos/Ball_For_MV.mp4 --no-edge-refine
py run_analysis.py --video data/videos/Ball_For_MV.mp4 --no-adaptive-hough
py run_analysis.py --video data/videos/Ball_For_MV.mp4 --edge-refine-band-px 6
```

В `key=value` конфиге: `no_edge_refine = true`, `no_adaptive_hough = true`, `edge_refine_band_px = 4`.

## Что пишет анализ

По каждому видео создается папка `output/analysis/<video_stem>/`:

- `summary.json` - машинно-читаемая сводка;
- `measurements.csv` - покадровые измерения (в т.ч. `ball_id` эпизода «шарик»);
- `summary.md` - короткий человекочитаемый отчет;
- `preview_sheet.jpg` - аннотированные контрольные кадры.

## Практические замечания

- Для production-замеров предпочитать режим `reference`, если в кадре есть референс с известным истинным размером.
- Для расчета массы LN2 нельзя подставлять в `cell_inner_diameter_mm` расстояние `ячейка-чехол`.
- Если целевая ошибка по массе жесткая, сначала проверять вклад `sigma_h / h`: при маленьком изменении уровня никакой точный диаметр ячейки уже не спасет.
- На длинных сериях обязательно хранить исходное видео, конфиг запуска и итоговые артефакты в одной папке серии.

## Симуляция без камеры

`py -3 run_analysis.py --simulate-check --simulation-output output/simulation_repeat --simulation-seed 900 --simulation-frames 24`

Создаёт десять размеченных сценариев, отдельно измеряет виртуальный эталон и проверяет детекцию, диаметр и ID. Выходная папка должна быть новой. Источники, допущения и границы: [методика](docs/SIMULATION_METHOD_RU.md). Независимые результаты: `output/simulation_holdout_900_20260930/validation.md` и `output/simulation_holdout_901_20260930/validation.md`. 29 модульных и интеграционных тестов прошли 01.10.2026; шесть интеграционных тестов требуют локального ClickHouse. Трекер использует глобальное сопоставление и прогноз скорости; многoобъектный анализ сохраняет субпиксельный радиус. Деформации и изменение глубины выявляют ограничения модели.

## Видео телефона

По умолчанию используется `pixel`: диаметр в пикселях, неизвестные mm/масштаб/неопределённость сохраняются NULL. Для тёмного шарика есть `--detector-profile dark-ball`, пиксельный диапазон, нормализованный ROI, `--dark-contrast-min` и `--dark-angular-contrast-min` (доля углов с нужным контрастом, по умолчанию 0.85). Полностью обрезанная окружность исключается. Профиль требует подготовленной сцены и не идентифицирует материал объекта.

`--annotated-video` сохраняет MP4 для просмотра; временные метки CSV являются источником времени. Сводка содержит `decode_status`: complete, limited_by_request или incomplete. Для предварительного размера при неизвестной неопределённости эталона используйте `--provisional-calibration`; этот статус сохраняется в протоколе, полная sigma остаётся NULL. Подтверждённая калибровка требует явно заданной `--calibration-sigma-mm`.

Подробные параметры и границы проверки: [PHONE_VIDEO_VALIDATION_RU.md](docs/PHONE_VIDEO_VALIDATION_RU.md). Повторение нескольких конфигураций: `scripts/run_video_manifest.py --manifest configs/video_manifest.example.json --output-root output/replay`. Сначала укажите свои исходные видео и калибровки в копии манифеста. Пароль ClickHouse берётся из среды.


## Устойчивое уточнение контура (01.10.2026)

Дополнительный пакетный режим `--edge-fit-method radial` использует радиальные градиенты, субпиксельные максимумы и геометрическую подгонку `soft_l1`. Проверяются угловая опора, остаток, эллиптичность и обрезание. Отказ не заменяется исходным Hough-радиусом. Кандидаты, поступившие на уточнение, записываются в таблицу `python_quality_v1` и `quality.json`; экспорт по UUID восстанавливает диагностику.

Настройки `--radial-polarity`, `--radial-min-coverage`, `--radial-min-gradient`, `--radial-max-axis-ratio` и `--edge-refine-band-px` фиксируются в протоколе. Тёмный профиль использует рост яркости наружу. Для малых архивных проекций проверена полоса25px; настройки требуют проверки на собственной оптике. Остаток подгонки не является физической неопределённостью. Основной пакетный CLI выбирает `radial` по умолчанию. `kasa` остаётся доступен для сравнения и для прежнего режима одного объекта. API-конфигурация `DetectionConfig()` сохраняет прежнее значение для совместимости; для повторения новых прогонов задают метод явно.

Трекер учитывает реальные интервалы времени. Недопустимые метки заменяются возрастающей оценкой, число замен сохраняется в сводке. Предсказания без контуров не записываются как измерения. CLI использует два потока OpenCV (`--opencv-threads`); на E3V2 четыре экспорта совпали побайтово с API-прогоном при16 потоках. Это проверка воспроизводимости, не контролируемый тест производительности.
