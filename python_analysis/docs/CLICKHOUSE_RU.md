# Хранение и анализ серий через ClickHouse

Основной CLI по умолчанию требует ClickHouse. `--offline` включает явный
локальный диагностический режим. Пакетная детекция выполняется Python/OpenCV;
результаты записываются в ClickHouse и повторно считываются из него перед
построением графиков и экспортом. SQL вычисляет медианы, средние, разброс по
траекториям, состав допустимой выборки и показатели обработанных кадров.

## Локальный сервер

`infra/clickhouse.compose.yaml`: образ `clickhouse/clickhouse-server:26.3.12.3`,
порт `127.0.0.1:8124`, БД `mvb_analysis`, пользователь `mvb`. Данные и логи
хранятся в отдельных постоянных томах проекта `mvb-analysis`. Другие контейнеры
ClickHouse не используются. Пароль задаётся переменной среды
`MVB_CLICKHOUSE_PASSWORD`; его нельзя помещать в исходники или отчёт.

```powershell
# Сначала задать MVB_CLICKHOUSE_PASSWORD через свою локальную конфигурацию.
docker compose -f infra/clickhouse.compose.yaml up -d
py -3 run_analysis.py --video data/videos/series.mp4 --calibration calibration.json --output-dir output/series_001 --frame-step 1
py -3 run_analysis.py --export-run UUID_ИЗ_СВОДКИ --output-dir output/reexport_001
```

Другой сервер задаётся `MVB_CLICKHOUSE_URL`, пользователь —
`MVB_CLICKHOUSE_USER`, БД — `MVB_CLICKHOUSE_DATABASE`. Для удалённого сервера
с паролем требуется HTTPS. Пароль передаётся HTTP-заголовком, не URL.
Запросы с UUID используют типизированные SQL-параметры; имена БД валидируются.
SQL-подключение реализовано через стандартную библиотеку Python и официальный
HTTP-интерфейс ClickHouse: https://clickhouse.com/docs/interfaces/http.

## Схема данных

- `python_runs_v1`: UUID серии, дата, SHA-256 видео, полный протокол параметров,
  версия среды, хеши исходников, калибровка и сводка. Эта запись фиксируется
  только после проверки числа записанных измерений и кадров.
- `python_measurements_v1`: UUID серии, индекс и время кадра, ID траектории,
  центр и радиус, пиксельный и метрический диаметры, масштаб,
  стандартная модельная неопределённость, референс, метод и опора на край.
- `python_frames_v1`: все обработанные кадры, включая пустые, время,
  число объектов и доступность масштаба.

Таблицы используют MergeTree и отдельные имена для Python-контура, чтобы
не смешивать их со схемами другого приложения. Исходные видео и изображения
хранятся файлами; в БД записываются ссылки, хеши и измерительные данные.
CSV/JSON/Markdown/PNG/JPG — производные экспорты. Для воспроизведения численных
экспортов и графиков исходное видео не требуется; аннотированный JPG создаётся
при первоначальной детекции и не восстанавливается одним SQL-запросом.

## Целостность

Каждый запуск получает новый UUID: повторный анализ того же видео — новая
серия с самостоятельными параметрами, а не перезапись прошлой. Межтабличная
транзакция не предполагается. Запись манифеста последней служит признаком
завершения; частичные записи без манифеста не доступны через `--export-run`.
Автоматических повторов INSERT нет. При сетевом сбое результат не объявляется
сохранённым; запуск повторяют с новым UUID. Частичные записи не удаляются
автоматически. Прямой SQL к таблицам должен учитывать наличие манифеста.

## Проверка 30.09.2026

21 тест прошёл, включая 4 интеграционных теста на реальном локальном
ClickHouse: точные медианы для чётных/нечётных выборок, независимость повторных
серий, пустая серия, обработка двух шариков и повторный экспорт, недоступность
незавершённой серии. Включение интеграционных тестов:

```powershell
$env:MVB_CLICKHOUSE_TEST = '1'
py -3 -m unittest discover -s tests -v
```

Без этой переменной 4 интеграционных теста пропускаются. Диагностические
симуляции выполняются отдельно; их старые протоколы и хеши не переписываются.
Проверка базы не подтверждает аппаратную точность измерений на стенде.
