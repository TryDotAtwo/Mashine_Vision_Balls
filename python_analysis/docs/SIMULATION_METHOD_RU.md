# Проверка машинного зрения без камеры

Дата: 30.09.2026. Код: `src/mvb/simulation.py`. Запуск через `run_analysis.py`.

## Источники и модель

Прочитан текст препринта ОИЯИ [P18-2024-60](https://www1.jinr.ru/Preprints/2024/060(P18-2024-60).pdf): уравнения охлаждения (5), толщины паровой плёнки (13), таблица П1. Локальная копия и метаданные: `data/documents/simulation_sources/`. Также прочитан локальный русскоязычный авторский вариант статьи «Using of frozen mesitylene beads with Rupert's droplet properties in cryogenic neutron moderators» из папки «Статья в ЭЧАЯ». Исторические результаты этих работ не являются экспериментами по текущему договору.

Для движения использовано уравнение (5) работы Gauthier [Self-propelled inverse Leidenfrost droplets](https://arxiv.org/html/1901.04218):

\[
m\dot v=15\rho gR^2\Delta h-15\mu_v vR^2/h,
\qquad \Delta h=1.45\,\mu\mathrm m.
\]

Коэффициенты 15 и перепад плёнки получены авторами для другой системы материалов. Их перенос на мезитилен — допущение генератора тестовых траекторий, физическая достоверность этого переноса не установлена.

Модель плёнки и охлаждения:

\[
h=\left(\frac{9k_v\mu_vR(T-T_b)}{\rho\rho_vgL_v}\right)^{1/4},
\qquad mc_p\dot T=-\frac{k_vA(T-T_b)}h,\quad A=2\pi R^2.
\]

Из таблицы П1 взяты: плотность жидкости 861.12 кг/м³, теплоёмкость 1750 Дж/(кг·К), вязкость пара 5.52·10⁻⁶ Па·с, теплопроводность пара 7.26·10⁻³ Вт/(м·К), плотность пара 4.5 кг/м³, теплота испарения 200000 Дж/кг, температура ванны 77.4 К. Диаметры тестовых объектов 3.2–4.2 мм соответствуют описанному диапазону изготовления; это параметры синтетических объектов, а не новые измерения.

Радиус фиксирован. Замерзание, внутренние полости, разрушение, взаимодействие шариков, гидродинамика жидкости и преломление на поверхности не моделируются. Движение у стенки отражается зеркально. Сценарий пересечения задаёт проекционные траектории вручную и не моделирует столкновение. Генератор ограничен двумя секундами; выполненные серии содержат 24 кадра при 30 кадрах/с.

## Изображение и калибровка

Проекция — модель камеры с центральной проекцией. Поле 40 мм, изображение 400×400, расстояние 50 мм и радиус ванны 17 мм выбраны для программной проверки; параметры реальной камеры ими не заменяются. Объекты имеют сглаженный контур и градиент яркости. Шум, размытие, блики, экспозиция и изменение масштаба задаются отдельно; их величины не оценены по аппаратуре. Деформация задаётся эллиптической проекцией с отношением осей 0.8.

Калибровка получена из отдельного синтетического видео эталона диаметром 3.7 мм, seed 730. Анализатор измеряет его пиксельный размер и сохраняет JSON масштаба; этот файл применяется ко всем проверочным сценам. Истинный размер проверяемых шариков не передаётся в измерительный алгоритм. Поиск ограничен диапазоном 2.8–4.6 мм. Для всех сценариев используются одинаковые параметры.

## Проверки и границы результата

Десять сценариев: одиночный шарик, два шарика, стенка, пересечение, временное исчезновение, шум и размытие, помехи, изменение масштаба, деформация, пустой кадр. Seed 40 использован при разработке. Независимые прогоны seed 900 и 901 выполнены после фиксации алгоритма; сохранены хеши исходников и проверена их неизменность во время запуска.

Генератор сохраняет AVI, точную покадровую разметку JSON и выборочные изображения/маски. Сопоставление с результатом проводится отдельной функцией по расстояниям центров, порог 0.6 истинного диаметра. Учитываются объекты с видимой площадью не менее 65%; сильные перекрытия исключены и отмечены отдельно. TP/FP/FN отражают найденные, ложные и пропущенные наблюдения. Смена ID считается по истории видимого объекта. RMSE диаметра вычисляется только для сопоставленных наблюдений; пропуски не исчезают из отчёта и остаются в FN.

Результаты находятся в `output/simulation_holdout_900_20260930/validation.md` и `output/simulation_holdout_901_20260930/validation.md`. Изменение глубины нарушает скалярную калибровку, а деформация — круговую модель. Успешная обработка выбранных синтетических сцен подтверждает работу программного контура, но не точность камеры или физической модели. Для метрологии нужны реальные эталоны, дисторсия и серии в рабочей среде.
