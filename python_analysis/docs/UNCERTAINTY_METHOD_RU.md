# Погрешности, методика измерения и коррекция по уровню азота

Документ фиксирует, как я считаю и раскладываю все существенные погрешности в эксперименте с шариком в жидком азоте. Это отдельная рабочая записка, чтобы не смешивать код, физику, геометрию стенда и изготовление ячейки.

## 1. Зачем нужна отдельная методика

В эксперименте есть два связанных, но разных измерения:

1. диаметр шарика по видео;
2. изменение уровня и масса испарившегося азота.

Они связаны через геометрию стенда:

- по мере испарения азота шарик опускается;
- при подливе азота шарик поднимается;
- при этом меняется расстояние от шарика до камеры;
- значит, меняется масштаб `мм/пикс`;
- значит, без поправки по высоте возникает систематическая ошибка в диаметре.

Именно поэтому диаметр ячейки и контроль уровня нужны не только для массы LN2, но и для коррекции видеометрии.

## 2. Условные обозначения

- `N_ball` - измеренный диаметр шарика в пикселях.
- `N_cell` - измеренный диаметр внутренней окружности ячейки в пикселях.
- `d_ball` - истинный диаметр шарика, мм.
- `D_cell` - внутренний диаметр ячейки, мм.
- `D0` - базовое расстояние от шарика до камеры в начальном положении, мм.
- `Delta h(t)` - изменение уровня азота относительно базового состояния, мм.
- `S` - масштаб `мм/пикс`.
- `theta` - горизонтальный угол поля зрения камеры.
- `Z` - оптическое увеличение/zoom factor.
- `N_x` - ширина кадра в пикселях.
- `rho` - плотность жидкого азота.
- `m` - масса испарившегося азота.
- `sigma_x` - стандартовая неопределенность величины `x`.

## 3. Полная измерительная цепочка

### 3.1 Видеометрия

1. Я снимаю видео шарика.
2. Из кадра выделяю шарик и ячейку.
3. По геометрии камеры или по референсу перевожу пиксели в миллиметры.
4. Корректирую масштаб на изменение расстояния до шарика, если меняется уровень LN2.
5. Получаю `d_ball ± sigma_d`.

### 3.2 LN2

1. Я измеряю изменение уровня `Delta h`.
2. Через внутренний диаметр ячейки считаю площадь сечения.
3. Через площадь и уровень считаю объем и массу испарившегося азота.
4. Получаю `m ± sigma_m`.

## 4. Базовые формулы

### 4.1 Масштаб по FOV

Если масштаб задается через геометрию камеры:

`S(D) = k_cal * 2 * D * tan(theta/2) / (Z * N_x)`

где `D` - текущее расстояние от шарика до камеры.

### 4.2 Диаметр шарика

`d_ball = N_ball * S(D)`

### 4.3 Масштаб по референсу

Если в кадре есть объект с известным размером:

`d_ball = D_ref * N_ball / N_ref`

где `D_ref` - истинный размер референса.

### 4.4 Масса испарившегося азота

`m = rho * A * Delta h`

`A = pi * D_cell^2 / 4`

## 5. Поправка из-за движения шарика по высоте

Это одна из ключевых поправок в моей постановке.

Если при испарении азота шарик опускается на `Delta h`, то расстояние до камеры растет:

`D(t) = D0 + Delta h(t)`

Соответственно масштаб меняется как:

`S(t) = S(D0 + Delta h(t))`

Для малых смещений:

`Delta S / S ~= Delta h / D0`

### 5.1 Практический вывод по текущим числам

Если взять:

- `D0 = 55 мм`;
- `Delta h = 6.3 мм`;

то:

`Delta S / S ~= 6.3 / 55 ~= 11.45%`

Это огромная систематика. Игнорировать ее нельзя.

То есть даже при идеальной детекции контура ошибка масштаба от вертикального движения шарика может быть порядка `11%`, если не ввести поправку.

## 6. Почему одного диаметра ячейки в кадре недостаточно

Если я использую внутреннюю окружность ячейки как референс в кадре, то я получаю масштаб для плоскости ячейки. Но шарик находится не обязательно в той же плоскости:

- ячейка зафиксирована;
- шарик движется по высоте вместе с уровнем;
- значит, масштаб для шарика и для плоскости ячейки не совпадает.

Поэтому режим `reference` по ячейке полезен, но его нужно сочетать с учетом `Delta h(t)`.

Практически это значит:

1. я измеряю `N_cell`;
2. я знаю `D_cell`;
3. я получаю масштаб для плоскости ячейки;
4. затем отдельно корректирую его на смещение шарика по высоте.

## 7. Полный список существенных погрешностей

### 7.1 Погрешности видеометрии

- `sigma_Nball` - ошибка детекции диаметра шарика в пикселях;
- `sigma_Ncell` - ошибка детекции диаметра ячейки в пикселях;
- `sigma_D0` - ошибка базового расстояния до шарика;
- `sigma_h` - ошибка измерения изменения уровня;
- `sigma_theta` - ошибка угла поля зрения;
- `sigma_Z` - ошибка zoom factor;
- `sigma_kcal` - ошибка калибровочного коэффициента;
- `sigma_tilt` - ошибка от наклона камеры;
- `sigma_distortion` - ошибка от дисторсии;
- `sigma_refract` - ошибка из-за окна/чехла и рефракции;
- `sigma_light` - ошибка из-за нестабильного освещения;
- `sigma_frost` - ошибка из-за инея, пузырей и загрязнений;
- `sigma_repeat` - межсерийный разброс.

### 7.2 Погрешности LN2 и ячейки

- `sigma_Dcell` - неопределенность внутреннего диаметра ячейки;
- `sigma_round` - некруглость, эллиптичность, конусность;
- `sigma_cyl` - отклонение цилиндричности по высоте;
- `sigma_h` - неопределенность изменения уровня;
- `sigma_rho` - неопределенность плотности LN2;
- `sigma_therm` - тепловой дрейф геометрии и свойств;
- `sigma_fill` - неопределенность при подливе и переходных процессах.

## 8. Разложение неопределенности по формулам

### 8.1 Для режима `fov` с учетом движения по высоте

`d_ball = N_ball * S(D0 + Delta h)`

Тогда:

`sigma_d^2 = (S * sigma_Nball)^2 + (N_ball * dS/dD * sigma_D0)^2 + (N_ball * dS/dD * sigma_h)^2 + (N_ball * dS/dtheta * sigma_theta)^2 + (N_ball * dS/dZ * sigma_Z)^2 + sigma_sys^2`

где `sigma_sys` собирает остаточные систематики:

- наклон;
- дисторсию;
- рефракцию;
- нестабильность света;
- загрязнение окна.

### 8.2 Для режима `reference`

`d_ball = D_ref * N_ball / N_ref`

Тогда:

`(sigma_d / d_ball)^2 = (sigma_Nball / N_ball)^2 + (sigma_Nref / N_ref)^2 + (sigma_Dref / D_ref)^2 + (sigma_z / D0)^2 + sigma_sys,rel^2`

Здесь `sigma_z` - неопределенность поправки по высоте шарика относительно плоскости референса.

### 8.3 Для массы LN2

`(sigma_m / m)^2 = (2 * sigma_Dcell / D_cell)^2 + (sigma_h / h)^2 + (sigma_rho / rho)^2`

Если `sigma_rho` мала относительно остальных вкладов, то на первом приближении можно ее опустить.

## 9. Как я оцениваю каждую погрешность на практике

### 9.1 `sigma_Nball`

Метод:

1. беру серию кадров с хорошо видимым шариком;
2. детектирую круг несколькими параметрами;
3. сравниваю результаты;
4. считаю разброс радиуса и остаток по кромке;
5. дополнительно вручную проверяю 20-50 кадров.

Хороший ориентир для качественного изображения:

- `0.3 ... 0.5 px` при хорошем контрасте;
- `1 px` и хуже, если есть блики, шум, иней.

### 9.2 `sigma_Ncell`

Метод:

1. снимаю сухую ячейку без шарика;
2. снимаю ячейку в рабочих условиях;
3. детектирую внутреннюю кромку по многим кадрам;
4. считаю средний радиус, разброс и эллиптичность.

### 9.3 `sigma_D0`

Метод:

- физическое измерение расстояния;
- повтор 5-10 раз;
- использование жесткого базирования и шаблона установки.

### 9.4 `sigma_h`

Метод:

- отдельное измерение уровня по видео или шкале;
- повторяемое чтение одной и той же сцены;
- проверка на dry-run и на подливе.

### 9.5 `sigma_tilt`

Метод:

- снимаю ячейку;
- если круг стабильно превращается в эллипс, есть наклон;
- оцениваю эллиптичность `b/a`;
- перенастраиваю механику.

### 9.6 `sigma_distortion`

Метод:

- снимаю линейку/эталон;
- смотрю изменение масштаба по полю;
- ограничиваю рабочую зону центром кадра;
- при необходимости ввожу калибровку.

### 9.7 `sigma_frost`, `sigma_light`

Метод:

- сравниваю dry-run и рабочий кадр;
- считаю detection ratio;
- считаю процент кадров с ложными кругами;
- повторяю серию с другой схемой света.

## 10. Как оценить геометрию уже существующей ячейки через CV

Поскольку ячейка уже есть какая есть, мне нужно оценить ее неопределенности не только штангенциркулем, но и компьютерным зрением.

### 10.1 Что именно нужно оценить

- средний внутренний диаметр;
- овальность;
- смещение центра по высоте;
- неоднородность кромки;
- воспроизводимость `N_cell` по кадрам и сериям.

### 10.2 Практический протокол

1. Снять ячейку без азота и без шарика.
2. Снять ячейку при нескольких положениях фокуса.
3. Снять ячейку с линейкой/эталоном.
4. На каждом кадре выделить внутреннюю окружность.
5. Для каждой детекции посчитать:
   - радиус;
   - центр;
   - остаток по окружности;
   - эллиптичность;
   - локальные отклонения по углу.
6. По серии построить:
   - средний радиус;
   - стандартное отклонение;
   - карту отклонений.

### 10.3 Что считать итоговой неопределенностью ячейки

Я рекомендую разделять:

- `sigma_Dcell,met` - метрологическая неопределенность истинного диаметра;
- `sigma_Dcell,cv` - неопределенность его CV-наблюдения в кадре;
- `sigma_round` - реальная некруглость.

Тогда в задаче видеометрии они входят по-разному:

- в масштаб по референсу входит CV-наблюдение;
- в массу LN2 входит истинный физический диаметр;
- в quality control важна некруглость как отдельный индикатор качества ячейки.

## 11. Почему контроль неизменности условий обязателен

Если я меняю:

- высоту камеры;
- угол камеры;
- свет;
- фокус;
- апертуру;
- расположение ячейки;

то я меняю не только картинку, но и численные значения всех `sigma`.

Поэтому одна серия должна идти в неизменных условиях.

В отчетах обязательно фиксировать:

- геометрию;
- оптику;
- свет;
- параметры камеры;
- версию кода;
- конфиг запуска.

## 12. Оценка достижимости целевой ошибки `0.01 мм`

### 12.1 Сенсор камеры

Для `MER2-231-41GM` по официальной странице:

- сенсор `IMX249`;
- пиксель `5.86 мкм`;
- `1920x1200`;
- `41 fps`;
- `GigE`;
- питание `12 ... 24 VDC`.

### 12.2 Первая оптическая оценка

Если эффективное увеличение в объектном пространстве `M`, то линейный шаг на объекте:

`p_obj = 5.86 мкм / M`

Representative scenarios:

| `M` | `мм/пикс` | `0.3 px` | `0.5 px` |
| --- | --- | --- | --- |
| `0.25` | `0.02344` | `0.00703 мм` | `0.01172 мм` |
| `0.50` | `0.01172` | `0.00352 мм` | `0.00586 мм` |
| `1.00` | `0.00586` | `0.00176 мм` | `0.00293 мм` |
| `2.00` | `0.00293` | `0.00088 мм` | `0.00147 мм` |

Вывод:

- целевой уровень `0.01 мм` принципиально достижим только при хорошем увеличении и субпиксельной стабильности;
- при `M < 0.25` цель уже на грани даже без систематик;
- реально нужно считать не только дискретизацию, но и свет, механику, фокус, наклон, уровень LN2.

### 12.3 Прикидка по проставочным кольцам

Для объектива `12.5 мм` и колец `0.5, 1, 5, 10, 20 мм` в первом приближении дополнительное увеличение около infinity-focus можно грубо оценить как:

`M_add ~= e / f`

Тогда:

| Суммарное удлинение `e` | `M_add` | `мм/пикс` |
| --- | --- | --- |
| `0.5 мм` | `0.04` | `0.14650` |
| `1 мм` | `0.08` | `0.07325` |
| `5 мм` | `0.40` | `0.01465` |
| `10 мм` | `0.80` | `0.00733` |
| `20 мм` | `1.60` | `0.00366` |
| `36.5 мм` | `2.92` | `0.00201` |

Это только прикидка первого порядка. Реальную рабочую схему нужно подтверждать калибровкой по эталону.

## 13. Что получается по текущему телефонному baseline

По smoke-прогону текущего кода на `data/videos/Ball_For_MV.mp4`:

- средний масштаб порядка `0.043 мм/пикс`;
- итоговая `sigma` среднего по серии была порядка `0.67 ... 1.16 мм` в зависимости от режима и отбора кадров.

Это не финальная метрология, а индикатор того, что без жесткой оптики, референса и контроля условий телефонный режим не дотягивает до целевых сотых миллиметра.

## 14. Ключевой вывод по уровню LN2 и допуску ячейки

Если:

- `h = 6.3 мм`;
- `sigma_h = 0.2 мм`;

то:

`sigma_h / h ~= 3.17%`

Следствие:

- цель `3%` по массе LN2 уже недостижима даже при идеальном `D_cell`;
- сначала надо улучшать измерение уровня или увеличивать `Delta h`;
- только потом спорить о сотых миллиметра на диаметре ячейки.

## 15. Что я считаю обязательным минимумом на следующем цикле

1. Отдельная серия с подшипником/эталоном.
2. Отдельная CV-оценка существующей ячейки.
3. Отдельная оценка `sigma_h` для уровня азота.
4. Фиксированная механика и свет.
5. Разделение:
   - геометрии стенда,
   - физического диаметра ячейки,
   - CV-наблюдаемого диаметра ячейки.

Без этого обсуждать итоговую точность бессмысленно.

## 16. Как отдельно оценивать `sigma_h`

Это очень важный пункт, потому что сейчас именно `sigma_h` может убивать весь бюджет.

### 16.1 Минимальная процедура

1. Выбрать способ чтения уровня.
2. Снять одну и ту же сцену много раз без реального изменения уровня.
3. Каждый раз независимо оценить `h`.
4. Посчитать стандартное отклонение.

Это и будет первичная оценка `sigma_h`.

### 16.2 Что нельзя делать

- считать `sigma_h` “на глаз”;
- подставлять желаемую цифру;
- переносить `sigma_h` из другой геометрии;
- считать, что подлив и испарение симметричны по неопределенности.

### 16.3 Что лучше сделать

- дать в кадр независимую шкалу уровня;
- автоматизировать считывание уровня по видео;
- оценить `sigma_h` отдельно для:
  - спокойного испарения,
  - подлива,
  - переходного режима после подлива.

## 17. Как измерять вклад межсерийной нестабильности

Даже если одна серия выглядит красиво, этого мало.

Я считаю обязательным:

1. снять минимум 3 серии в одной конфигурации;
2. прогнать один и тот же алгоритм;
3. сравнить:
   - средний диаметр;
   - стандартное отклонение;
   - detection ratio;
   - итоговую sigma среднего.

Если результаты сильно расходятся между сериями, значит, доминирует не модель пикселя, а неустойчивость постановки.

## 18. Как проверять достижимость `0.01 мм` честно

### 18.1 Нельзя

- просто взять шаг пикселя и назвать его итоговой точностью;
- игнорировать вертикальное движение шарика;
- игнорировать наклон, дисторсию и блики;
- брать лучший кадр вместо серии.

### 18.2 Нужно

1. сделать эталонную серию;
2. посчитать CV-ошибку;
3. посчитать межсерийный разброс;
4. отдельно посчитать вклад уровня;
5. только потом сравнить итоговую sigma с `0.01 мм`.

## 19. Разделение случайной и систематической частей

Я считаю полезным явным образом разделять:

- случайную компоненту:
  - шум детекции,
  - шум уровня,
  - межкадровый разброс;
- систематическую компоненту:
  - неправильный масштаб,
  - неверный внутренний диаметр ячейки,
  - наклон камеры,
  - рефракцию,
  - неверную модель положения шарика.

Если их не разделять, итоговая цифра «погрешности» становится бесполезной.

## 21. Отдельно про подлив азота

Подлив нельзя рассматривать как просто “тот же процесс, только наоборот”.

При подливе возникают дополнительные эффекты:

- переходная турбулентность;
- скачок уровня;
- изменение контраста;
- временное ухудшение детекции шарика;
- возможное нарушение предположения о квазистационарности сцены.

Поэтому для подлива нужно:

1. отдельно маркировать момент подлива;
2. отдельно выделять переходный интервал;
3. не смешивать этот интервал с квазистационарной частью серии.

## 22. Как связать все это с будущей автоматизацией

Когда программа начнет выдавать сигнал на насос, ей нужно будет опираться не на “сырую картинку”, а на устойчивые критерии:

- положение шарика;
- тренд изменения уровня;
- качество текущей детекции;
- блокировку на переходный режим после предыдущего подлива.

Иначе контур управления будет принимать решения по шуму.

## 23. Финальный смысл документа
